## `docs-1` — corpus-facts.json: one measured source for every number, rendered into docs, README and tool descriptions, with a numeral linter that fails CI on an unbacked figure

**survived 3/3, with corrections · effort L · impact 5/5**

**What the code does today.** Every corpus number is retyped by hand at each surface. Counted in this session (excluding audit.md, years, ports and HTTP codes): 435 numeral occurrences, 149 distinct values; `6,876` appears in 22 files, `36%` in 11, `279` in 6, `1,735` in 6, `257`/`2,212` in 5 each. Two discrepancies survive both audits because only arithmetic finds them: scripts/harvest.py:62 says the unreachable remainder is `141,032 documents (1.75%)`, while docs/how-it-works/data-sources.md:61 gives `7,941,378 of 8,082,496`, whose difference is 141,118 (86 apart); docs/tools/df-search.md:68 shows sample output `showing 2 of 277 records` for `konung`, while data-sources.md:150 records that the apparatus fix moved `konung` from 277 to 279 — the sample output predates the fix. The open `27` (search-tips.md:88) vs `28` (df_tool.py:110) compound-language count is only decidable by arithmetic too: 6,876 minus the seven language counts in df_tool.py:106-113 equals the stated 833 `no language` only if compounds are 28. The site already configures `pymdownx.snippets` with `base_path = ["."]` (zensical.toml:95-96) and docs.yml:2-6 deliberately drops its path filter because of it — yet no page uses a snippet (grep for `--8<--` finds nothing), so the include mechanism for generated tables is wired and idle. The percentages are derived by hand as well: `36%` is 2,464/6,876 = 35.8, `60%` is 4,142/6,876 = 60.2, `44% plurality` (dataset.py:149) refers to ruotsi 3,045/6,876 = 44.3 while the same sentence cites the 2,870 Latin/German count, which is 41.7% (test_retrieval_quality.py:19 says `42%`).

**The gap.** Two audits corrected numbers by reading; the third drift instance (141,032 vs 141,118) and the fourth (277 in sample output) were found here by arithmetic, not reading. Nothing in the repository knows what the numbers are, where they came from, or which prose repeats them. Every re-harvest (the README says the index moves) invalidates an unknown subset of ~150 figures across ~30 files, and the only correction mechanism is another full read.

**The proposal.** 1) `scripts/measure_corpus.py <jsonl> --out docs/facts/df.json` (the spike in the scratchpad is 80 lines and already computes the schema): record counts, `untranscribed {count,pct}`, `no_end_year`, `no_year`, `located`, `no_place`, `no_country`, `no_language`, `language` (per label, plus `compound_language`), `place_vocabulary.size`, `indexterm_vocabulary.size` and issuer/type counts, `country`, `by_century`, `year_range`, `df_number_range` (the `1 to 6888` in df_tool.py:214 and formatter.py:89 become a rendered value), `apparatus` (records with superscripts/brackets, occurrences), and a `queries` block produced by ingesting into a temp LanceDB and running the exact queries the prose argues from: bref/breff/overlap, konung/konungen at fuzzy 0 and 1, de/den/om, Åbo, Tallinn/Reval, kirkko/Kirkolliset, `or`, plus `harvest` (coverage_pct, index_total, documents_written, unreachable, shortfall cells — read from `.data/df/report.json`, and derived rather than retyped). Commit the JSON (≈3 KB) with `source_sha256` and `measured_at`. 2) Rendering: `scripts/render_facts.py` writes `docs/facts/df-*.md` tables (corpus overview, language labels, place vocabulary top-20, index-term issuers/types, century histogram, spelling-variant table) which pages include with `--8<-- "docs/facts/df-languages.md"`; hand-written sentences keep their voice but numerals in them become `{{facts.untranscribed.pct}}`-style placeholders resolved by the same renderer into a generated sibling (`search-tips.md` → source `search-tips.src.md`), the way `uv lock` produces `uv.lock` — with `render_facts.py --check` in `dagger call checks` failing when the committed output is stale. 3) `df_tool.py` and `tools.py` build their description strings with `str.format_map(FACTS)` from a package-data copy `ra_mcp_kansallisarkisto_mcp/facts/df.json` (installed with the wheel; ~3 KB), so the tool text the model sees and the site table come from one file. 4) `scripts/check_numerals.py`: every comma-grouped or ≥3-digit numeral in docs/**, README.md, SECURITY.md, the two src packages and scripts/ must be a value in df.json (or a derived pct within ±0.5 of one), a year, or listed in `docs/facts/allowlist.txt` with a one-line reason (`10,000 — MAX_TOTAL_COUNT`, `54 — Trivy findings, security.md`). Wire it into `Checks` in .dagger/checks.go. 5) Corpus-only test in test_search_invariants.py: when `.data/df/df.jsonl.gz` exists, regenerate and assert equality with the committed JSON, so a re-harvest that changes a fact is a failing test rather than a surprise. Every generated table carries a footer line `measured <date> by scripts/measure_corpus.py from df.jsonl.gz sha256 <8 chars>` — the link from the number to its measurement.

**Why it is once-in-a-lifetime.** This repository's distinguishing property is that its prose argues from exact counts; the audits proved that property decays at the rate of one drift per commit series. Ending drift structurally — numbers that are outputs of a script, prose that cannot compile with a stale figure, and a CI gate that names the unbacked numeral — is what makes 'the prose is load-bearing' true in 2036 rather than a claim about 2026. It is also the precondition for the two larger corpora: `tuomiokirjat` would add hundreds of figures nobody could keep by hand.

**How we would know.** `check_numerals.py` reports 0 unbacked numerals on main (today it would report ≥2 contradictions and ~40 single-source figures with no measurement); the 141,032/141,118, 277/279 and 27/28 pairs are impossible to reintroduce; a re-harvest updates every page and both tool descriptions in one commit whose diff is the JSON plus generated files; the corpus-only equality test is green on the maintainer's machine.

**Risks.** Argues against the project's habit of hand-sharpened prose (commit f84c229 'sharpen the tool descriptions against the live service'): templated numerals can read mechanically if sentences are also generated — keep sentences hand-written and substitute only numerals. The real corpus cannot be harvested here (proxy 403), so the first df.json must be seeded from today's docs and marked `provisional: true` until a maintainer runs the script; the linter will immediately flag the 86-document contradiction and someone must decide which number is right. Zensical has no macros plugin, hence the render-to-sibling design; it doubles some markdown files in the tree. Format-string braces in existing descriptions (`{`) must be escaped.

**First step.** Land `scripts/measure_corpus.py` (from the spike) plus `docs/facts/df.json` seeded from the current docs with `provisional: true`, and `scripts/check_numerals.py` run in report-only mode in `make check`; open one issue listing the numerals it cannot back, starting with 141,032 vs 141,118 and 277 vs 279.

**Spike.** Done in the scratchpad: `corpus_facts.py` produces the full facts schema from the 18-row fixture in 1.4 s including a temp LanceDB ingest and 13 measured queries (fixture reproduces the documented behaviours — `konungen` fuzzy=1 collapses to 0, `kirkko` = 0, `Abo` = `Åbo` = 7); `numerals.py` inventories 435 occurrences / 149 distinct numerals across the prose surfaces and lists spread per value. Re-run: `/tmp/uvenv/bin/uv run python <scratchpad>/spike/corpus_facts.py packages/kansallisarkisto-lib/tests/fixtures/df_sample.jsonl`.

## `docs-2` — Executable examples: every tool call shown in prose runs against the fixture in CI, sample outputs are regenerated not retyped, and the fixture gains the charters the examples cite

**survived 3/3, with corrections · effort M · impact 4/5**
