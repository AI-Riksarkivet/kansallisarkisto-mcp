Delete the mocked Unreadable class in test_server.py once the real fault exists. Add the 'appended_unindexed' case as a documented canary: a test named test_rows_added_without_reindex_are_invisible_to_search_but_visible_to_get_charter that pins the split-brain so anyone adding an append path meets it.

**Why it is once-in-a-lifetime.** The project's headline operational promise is 'boots without data; a missing table is a message'. This makes the stronger promise true: no state of the mounted directory can produce a green server that returns empty answers. Nothing in the reference implementation (ra-mcp) or the siblings has this; it is the difference between 'the probe exists' and 'the probe is proven against every way a lance directory can be wrong'.

**How we would know.** Five fault modes each pinned by a test; for all five, /ready returns 503 and the boot log names the fault; the number of tests that mock lance falls from 1 to 0; the half-built-table state that today returns 0 hits with readiness=(True,'df') returns 503.

**Risks.** readiness() gains a real search per probe (measured ~5-25 ms on the fixture; an orchestrator polling every 10 s is negligible, but document it). Checking list_indices() couples readiness to lancedb's index metadata API, which has moved between releases (see testing-3). The EACCES case can only run as non-root, so it lives in test-mcp, not in the 7-second suite.

**First step.** Add test_faults.py with only the 'no_fts_index' case asserting readiness() is (False, ...) — it fails today — then change readiness()/probe_table_readable to require an FTS index with zero unindexed rows and a probe keyword that must hit. One PR, ~80 lines.

## `testing-3` — Prove the declared dependency floor and the table-format contract between the ingest machine and the image

**survived 3/3, with corrections · effort S · impact 4/5**

**What the code does today.** packages/kansallisarkisto-lib/pyproject.toml declares lancedb>=0.20,<1 and pyarrow>=18,<25.
