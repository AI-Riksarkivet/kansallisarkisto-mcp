## `philology-1` — The ordinal sign º (U+00BA) is a letter to the tokeniser: every Roman-numeral date is an unfindable token, and the test that guards it checks the wrong character

**survived 3/3, with corrections · effort S · impact 4/5**

**What the code does today.** models.py:23 `_FOOTNOTE_MARKS = re.compile(r"[⁰-₟°²³¹]+")` strips the DEGREE SIGN (U+00B0) but not the MASCULINE ORDINAL INDICATOR (U+00BA), which is what the DF edition actually uses after Roman numerals: fixture DF 404 `mcccxxxº tercio`, DF 526 `mcccxlº septimo`, DF 1086 `mºccccº * nono` (3 of the 15 transcribed fixture records, 20%). Unicode category of º is Lo (letter), so tantivy's `simple` tokenizer keeps it inside the token. Measured on the fixture: `mcccxl` exact = 0 hits, `mcccxlº` = DF 526; `mcccxxx` = 0; `mcccc` = 0 (and fuzzy=1 also 0 for `mccccº`). test_retrieval_quality.py:47 pins `("M°CCC°XL", "MCCCXL")` with U+00B0 — a character that does not occur in the fixture at all (the non-ASCII census shows 4 × U+00BA, 0 × U+00B0), so the guard passes vacuously against the real edition. Nothing in the tool descriptions (df_tool.py:64-85, tools.py:19-68) explains the edition's sigla either: `(ͻ: nadh)` = editor's emendation ('read'), `(!)` = sic, `…` = omission, `*` = footnote, `etc:a` = abbreviated etcetera — all present in the fixture and all shown raw in snippets.

**The gap.** A historian who types the year the way the charter writes it (`mcccxl`, `anno mccccº`) gets zero. Dating-by-Roman-numeral is the single most common way a medieval Swedish/Latin charter states its own date, and it is currently invisible to search. Meanwhile a model reading `met Gudhz nampn (ͻ: nadh)` has no way to know that `nadh` is the editor's word and `nampn` the scribe's.

**The proposal.** (1) models.py:23 — add `ºª` to the class, and add a fourth case to the parametrize list at test_retrieval_quality.py:35-51 using the real characters: `("mcccxlº septimo", "mcccxl septimo")` and `("mºccccº nono", "mcccc nono")`. (2) Add a corpus sweep to `test_full_corpus_reachability_is_understood` (test_retrieval_quality.py:165) counting tokens matching `[a-z]+º` before/after the strip, so the number is recorded next to the 2,266/4,801 figures. (3) Add one sentence to the `df_get_charter` description (df_tool.py:202-211) and to search-tips.md §'The edition's apparatus': the FMU sigla legend — `(ͻ: X)` read X, `(!)` sic, `[X]` editorial supplement, `…` omitted by the editor, superscript digits = footnote numbers, `*` = footnote without number. (4) In `_render_charter`/`format_charter` (formatter.py:66-110) keep the transcript verbatim but append the legend once per answer when the text contains `ͻ`, `(!)` or a superscript, so the model can read the apparatus rather than quote `nampn (ͻ: nadh)` as if it were the text.

**Why it is once-in-a-lifetime.** The project's signature move is that every unfindable-word class was measured and closed. This is the one it missed, and it missed it because the pinned test used a look-alike character. Closing it with the real bytes, and documenting the edition's sigla for the model, is what makes the apparatus-handling story complete rather than 90% complete.

**How we would know.** On the fixture: `mcccxl`, `mcccxxx`, `mcccc` go from 0 to 1 hit each; the new parametrize cases pass; the corpus sweep reports the number of º-fused tokens (expected in the hundreds, since 3/15 transcribed fixture charters carry one) and asserts 0 after ingest. A model answer for DF 526 explains `(ͻ: nadh)` correctly in a smoke prompt.

**Risks.** None to behaviour beyond recovered recall; U+00AA (ª) is added on the same reasoning and should be confirmed absent-or-apparatus in the full corpus. The legend adds ~120 chars to a charter answer only when sigla are present.

**First step.** One PR: extend the regex at models.py:23, replace the U+00B0 test case with the two U+00BA cases, add the º sweep to the corpus-only test, and add the sigla sentence to the two descriptions and search-tips.md.

## `philology-2` — Tell the model what kind of text it is reading: DF transcripts are edition text, not HTR, and `language` is the language of the original, not of the transcript

**survived 3/3, with corrections · effort S · impact 3/5**

**What the code does today.** df_tool.py:79 'The text is machine-recognised, so check any quotation against the source'; tools.py:62-63 'the transcripts are OCR/HTR output over a millennium of handwriting'; search-tips.md:127-131 'These are OCR and handwritten-text-recognition outputs over a millennium of handwriting, not proofread transcriptions.' The fixture shows what the text actually is: Hausen's FMU edition with its full apparatus — numbered footnotes, `(ͻ:` emendations, `[n]` supplements — i.e. a proofread scholarly edition (possibly OCR'd from print, never HTR of the parchment). The `language` field: all three `venaja` records in the fixture (DF 1, 4, 5) are Swedish translations of the Primary Chronicle ('Efter syndafloden delade Noaks tre söner…', '[År 882.] Drog Oleg…'); the field describes the source document, and the 89 `venaja` charters corpus-wide are almost certainly all Swedish-text translations. The language description at df_tool.py:110-118 and the instructions at tools.py:23-27 say nothing of this, and Low German letters open with Latin formulas ('Salutacione etc.', 'Obsequiosam in beneplacitis voluntatem cum salute premissa', DF 891/1053) while labelled `saksa`.

**The gap.** Both statements steer a historian wrong in opposite directions. Calling an edition 'HTR' makes the model over-hedge quotations from a text that is, for scholarly purposes, citable as FMU; and a user asking 'give me the Swedish-language charters' with `language='ruotsi'` silently loses every Swedish-text `venaja` record, while a user filtering `language='venaja'` expecting Russian gets Swedish. When tuomiokirjat (real HTR) lands, the two corpora need different warnings, and today there is one string for both.

**The proposal.** Introduce a per-corpus `TextStatus` in the lib (e.g. `models.py`: `DF_TEXT_STATUS = 'edition'` with a one-line human description: 'text of the printed edition Finlands medeltidsurkunder / Registrum Ecclesiae Aboensis as carried by Diplomatarium Fennicum, with editorial apparatus; not a manuscript HTR'), and have `format_charter` (formatter.py:86-110) print it as a `Text:` line under `Language:`. Rewrite df_tool.py:79 and tools.py:62-63 to say 'edition text, so quote it as the edition (FMU/REA via DF n) and check the apparatus, not as a manuscript reading'; reserve the HTR warning for the corpora that are HTR. For `language`: change the field description (df_tool.py:110-118) to 'language of the original document as catalogued; the transcript of the 89 `venaja` records is a Swedish translation, and German letters carry Latin formulas — filter on it as provenance, not as the language of the words you will search'. Add a test in test_retrieval_quality.py that every `venaja` fixture record's transcript contains ≥3 of {'och','af','till','som','de'} and none of the Cyrillic block.

**Why it is once-in-a-lifetime.** The repository's entire claim is that a historian can trust what the server says about the material. Misdescribing an edition as HTR and a provenance label as a text language are the two mis-statements a medievalist notices in the first minute and never forgets. Getting text status right per corpus is also the precondition for citing to scholarly standard (philology-6).

**How we would know.** The three prose sites agree with a single `TextStatus` constant, asserted by a test in the style of test_search_invariants.py:80-85 (`'edition' in df_search.__doc__` pattern). The venaja test passes on the fixture and on the full corpus (`.data/df` present). A smoke prompt 'Which of these are in Russian?' over DF 1/4/5 yields 'Swedish translations of Russian chronicle passages'.

**Risks.** The claim that DF text is edition text should be confirmed against df.kansallisarkisto.fi for the account-book entries (`Tili- ja pöytäkirjamerkinnät`, 1,007 records), some of which may be DF's own transcriptions; wording should say 'edition or DF transcription' if so. Argues mildly against the current uniform 'machine-recognised' hedge, which was the safer generic claim.

**First step.** One PR: add the constant and the `Text:` line, edit the two descriptions and search-tips.md:127-131, add the venaja-is-Swedish test, and update docs/tools/index.md:107-115 ('What every result carries').
