## `devx-1` — Corpus-free first search: `make fixture-db` and an in-process `ka-query` CLI that prints exactly what the model sees

**survived 3/3, with corrections · effort S · impact 4/5**

**What the code does today.** README.md:39-45 quick start is `make install; make harvest; make ingest-df`, and docs/getting-started/local.md:7-10 lists 'a harvested Sisältöhaku export' as a requirement. `make harvest` (Makefile:11-12) hits sisaltohaku.demo.kansallisarkisto.fi — a *demo* host that answers 403 from this environment. The only corpus-free searchable server is inside Dagger: `fixtureData` (.dagger/serve.go:21-34) ingests packages/kansallisarkisto-lib/tests/fixtures/df_sample.jsonl into /tmp/lancedb and `ServeUp` mounts it. scripts/ingest_df.py:29-38 already accepts `--jsonl`/`--output`. There is no way to call a tool from a shell: `make inspect` (Makefile:31-32) is `npx @modelcontextprotocol/inspector` (floating, needs Node); the lib is callable but bypasses `_answer` (df_tool.py:31-56) and the formatter, so a developer never sees the exact text the model gets. Measured: fixture ingest+index is 0.04 s; `df_search('konung')` on it is 7 ms.

**The gap.** The path from clone to 'I searched something and read the model-facing text' requires either network to a demo service or Dagger+Docker. The project's own 18-charter fixture — chosen to cover every documented trap — is the ideal onboarding corpus and is unreachable outside pytest and the Dagger engine.

**The proposal.** (a) Makefile target `fixture-db`: `uv run python scripts/ingest_df.py --jsonl packages/kansallisarkisto-lib/tests/fixtures/df_sample.jsonl --output data` — after it, `uv run kansallisarkisto-mcp` and `claude mcp add …` work with zero network; server boot log already says `tables: df`. (b) A console script `ka-query` in packages/kansallisarkisto-mcp/pyproject.toml `[project.scripts]` → `ra_mcp_kansallisarkisto_mcp.cli:main`, ~60 lines: argparse mirroring df_search's parameters (keyword, --limit, --offset, --language, --issuingplace, --country, --year-min, --year-max, --any (match_all=false), --fuzzy 0-2) plus `ka-query charter 1031` and `ka-query tools` (dump tools/list + instructions). It drives the in-memory `fastmcp.Client(tools.kansallisarkisto_mcp)` exactly as packages/kansallisarkisto-mcp/tests/test_tools.py:20-23 does, so the output is byte-identical to what a model receives — `_answer`, `_oneline` anti-forgery, snippet truncation, error sentences included. (c) README quick start becomes: `make install && make fixture-db && uv run ka-query konung --fuzzy 1`, with `make harvest` as the 'now get the real corpus' step. (d) A pytest test runs `ka-query` via subprocess against the fixture so the onboarding command is itself under test.

**Why it is once-in-a-lifetime.** Reference implementations are copied by people who can run them in ten minutes offline. Making the trap-covering fixture the default first corpus means every newcomer (and every future sibling corpus port) starts by seeing untranscribed charters, year-0, mixed place names and phrase queries rendered the way a model reads them — the project's hardest-won knowledge becomes the first thing you touch, not the last.

**How we would know.** On a fresh clone with the wheel cache warm and no network: `make fixture-db && uv run ka-query konung` completes in under 5 s (ingest 0.04 s + interpreter/import ≈ 1.5 s measured for the smoke run). Time-to-first-search for a newcomer drops from 'needs Dagger or the demo host' to one Make target. `ka-query tools` output equals `tools/list` from the HTTP transport (asserted by a test).

**Risks.** `data/` is the resolved URI (config.py:46-62 step 2), so a developer who later runs `make ingest-df` overwrites the fixture table — desirable, but `ingest_df` uses mode='overwrite' (ingest.py:144) so say so in the target comment. The CLI must not become a second tool surface: it should introspect the registered FastMCP tool's schema rather than re-declare parameters, or it will drift exactly like docs/tools/df-search.md did.

**First step.** Add the `fixture-db` target and the README line; add `cli.py` with `query`, `charter`, `tools` subcommands driving the in-memory Client; one subprocess test. ~120 lines, one PR.

**Spike.** Already run here: `uv run python scripts/ingest_df.py --jsonl packages/kansallisarkisto-lib/tests/fixtures/df_sample.jsonl --output <scratch>/fxdb` (0.04 s, 18 rows), then `KA_LANCEDB_URI=<scratch>/fxdb uv run kansallisarkisto-mcp` boots and `/ready` answers `{"status":"ready","table":"df"}`. For the CLI: `uv run python -c "import asyncio; from fastmcp import Client; from ra_mcp_kansallisarkisto_mcp import tools; print(asyncio.run(Client(tools.kansallisarkisto_mcp).__aenter__()) )"` pattern from test_tools.py:20-23 — set `KA_LANCEDB_URI` and call `df_search` with `{'keyword':'konung','fuzzy':1}` to see the exact model-facing text.

## `devx-2` — `make ci-local` and `make smoke-local`: the Dagger pipeline's checks and its MCP smoke test runnable with uv alone, Dagger kept for the image-only 10%

**survived 3/3, with corrections · effort M · impact 5/5**

**What the code does today.** Makefile:66-69 `ci` is three `dagger call`s; `test-mcp` (Makefile:61-62) exists only as `dagger call test-mcp`. .dagger/testmcp.go:24-44 builds the image, ingests the fixture, and runs scripts/mcp_smoke.py with `MCP_URL=http://kansallisarkisto-mcp:8000/mcp` — but mcp_smoke.py:16 reads `MCP_URL` from the environment and nothing in it is image-specific. `make check` (Makefile:43-44) is `format lint typecheck` where `lint` is `ruff check --fix` — it mutates, so there is no local verify-only equivalent of what CI gates on. docs/development/index.md:67-69 states Dagger 'drives checks, tests, builds, local serving and releases identically on a laptop and in CI'. Verified here without Dagger: `uv run ruff check .` 0.04 s, `ruff format --check .` 0.03 s, `uvx ty check` 1.1 s, `pytest` 7.1 s, and mcp_smoke.py against `KA_MCP_TRANSPORT=http PORT=18765 uv run kansallisarkisto-mcp` over the fixture table: 6/6 PASS in 1.19 s. The CI equivalents took 67 s + 17 s + 29 s (run 34360630378).

**The gap.** The deepest test in the repository — 'the only place the index configuration is verified end to end' (ci.yml:34-38, testmcp.go:13-15) — cannot be run by a contributor without Dagger + a container runtime, yet 90% of what it verifies (ingest → FTS config → HTTP transport → tool dispatch → formatter) needs neither. The remaining 10% (glibc wheels, USER 1000 + mode-0600 ownership, the purged-Debian entrypoint) is what Dagger genuinely buys, and it is not separated from the rest.

**The proposal.** Makefile: `verify: ruff format --check . ; ruff check . ; ty check` (no mutation; `check` stays as the fixer). `smoke-local`: a 25-line `scripts/smoke_local.py` (or shell) that ingests the fixture to a temp dir, starts `kansallisarkisto-mcp` as a subprocess with `KA_MCP_TRANSPORT=http`, `KA_LANCEDB_URI=<tmp>`, `PORT=0`-style free port, `FASTMCP_CHECK_FOR_UPDATES=off`, polls /ready (not /health — readiness is the honest signal), runs mcp_smoke.py with `MCP_URL`, kills the server; exit code propagates. `ci-local: verify test smoke-local` — target time under 15 s. Rename the Dagger function's contract in docs: `dagger call test-mcp` = 'the same smoke test against the *production image*', and add one image-only assertion there that local cannot make (e.g. `id -u` == 1000 and `/usr/bin/perl` absent inside the served container) so the split is explicit. Move mcp_smoke.py's 6 checks into a shared `smoke_checks(client)` function imported by both paths. docs/development/index.md gets a two-column table: 'runs with uv' vs 'needs Dagger', with what each proves.

**Why it is once-in-a-lifetime.** This is the hermetic-without-Dagger 90% case. A contributor gets the full CI verdict — including the end-to-end index-config check — in the time it takes to read the diff, and Dagger becomes what it should be here: the proof about the *artifact*, not the gatekeeper of the *code*. Sibling projects (ra-mcp, ape-mcp) inherit the same shape.

**How we would know.** `make ci-local` green in ≤ 15 s on a laptop with warm caches (measured components sum to ~10 s), with no Docker daemon and no Dagger CLI installed. Every check that fails in ci.yml also fails in `make ci-local` except the enumerated image-only assertions. The docs table lists exactly which assertions are Dagger-only.

**Risks.** Two paths can drift — the mitigation is that both call the same `smoke_checks()` and the same ruff/ty/pytest invocations (put the commands in one place: a `scripts/ci_steps.py` or `[tool.ci]`-style table the Go module and the Makefile both read is over-engineering; a comment cross-reference plus a test that greps checks.go for the same flags is enough). This argues against the stated 'identically on a laptop and in CI' Dagger philosophy (docs/development/index.md:67-69); the honest reframing is 'identically for the image; instantly for the code'. Windows contributors need the subprocess launcher to avoid shell-isms — write it in Python.

**First step.** Add `verify`, `smoke-local`, `ci-local` targets and `scripts/smoke_local.py`; refactor mcp_smoke.py's body into `smoke_checks(client)`; update the Makefile table in docs/development/index.md. One PR, no Go changes.

**Spike.** Run here: ingest fixture to a scratch dir; `KA_LANCEDB_URI=<dir> KA_MCP_TRANSPORT=http PORT=18765 FASTMCP_CHECK_FOR_UPDATES=off uv run kansallisarkisto-mcp &`; poll `curl -s localhost:18765/ready` until 200; `MCP_URL=http://127.0.0.1:18765/mcp uv run python scripts/mcp_smoke.py`.
